# النشر على Cloudflare Pages

> **الموقع منشور:** https://libyaprotech.com
> مربوط بـ Git على الفرع `main` — كل دفعة تُنشر تلقائياً بلا أي أمر.

الموقع ثابت بالكامل: لا خطوة بناء، ولا اعتماديات، ولا متغيرات بيئة.

## إعدادات المشروع في لوحة Cloudflare

| الحقل | القيمة |
|---|---|
| Framework preset | None |
| Build command | *(اتركه فارغاً)* |
| Build output directory | `/` |
| Root directory | `/` |
| Production branch | `main` |
| Node version | غير مطلوب |

## الخطوات

1. `dash.cloudflare.com` ← **Workers & Pages** ← **Create** ← **Pages** ← **Connect to Git**.
2. اختر مستودع `tsallabi/Libya-Pro-tech` وامنح الصلاحية إن طُلبت.
3. املأ الحقول بالجدول أعلاه ثم **Save and Deploy**.
4. أول نشر يستغرق أقل من دقيقة، والنتيجة على `https://<project>.pages.dev`.
5. كل دفعة جديدة إلى `main` تُنشر تلقائياً، ودفعات الفروع الأخرى تُنشر كمعاينات.

## النطاق المخصص

**Custom domains** ← **Set up a domain** ← أدخل النطاق.
إن كان النطاق داخل Cloudflare يُضبط تلقائياً، وإلا أضف سجل `CNAME` يشير إلى `<project>.pages.dev`.
بعد ربط النطاق حدّث الرابط في `robots.txt` و`sitemap.xml`.

## ملفات النشر في المستودع

- `_headers` — ترويسات الأمان وسياسة التخزين المؤقت: اللقطات سنة كاملة غير قابلة للتغيير، الأصول يوم، ملف البيانات خمس دقائق، والصفحة نفسها تُراجَع في كل طلب.
- `404.html` — صفحة الخطأ بهوية الموقع، تلتقطها Cloudflare Pages تلقائياً.
- `robots.txt` و`sitemap.xml` — للفهرسة.

## سياسة أمان المحتوى

مضبوطة في `_headers` وتسمح فقط بما يحتاجه الموقع: خطوط Google، صور من نفس المصدر، إطارات الديمو عبر HTTPS، وإرسال النموذج إلى واتساب. لا توجد أنماط أو سكربتات مضمّنة في HTML، لذا لا حاجة إلى `unsafe-inline`.
فُحصت السياسة محلياً بخادم يطبّقها فعلياً، ولم تظهر أي مخالفة.
